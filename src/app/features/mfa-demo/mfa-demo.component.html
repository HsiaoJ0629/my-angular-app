TOTP (RFC 6238) from first principles

I implemented OTP and TOTP second factors across Attvest's financial platforms. This page re-implements TOTP with no libraries — just the Web Crypto API — and runs both halves in your browser: the authenticator that shows a code, and the server that decides whether to accept it.

The implementation is checked against every test vector in RFC 4226 and RFC 6238. Read the source (opens in a new tab)

How a code is made
  1. Counter. T = floor(unix time ÷ 30), written as an 8-byte big-endian integer. JavaScript's bitwise operators are 32-bit, so the counter is written as two 32-bit halves rather than shifted into place.
  2. HMAC. HMAC-{{ algorithm() }}(shared secret, counter).
  3. Dynamic truncation. The low 4 bits of the last digest byte pick a 4-byte window; its top bit is masked off to give a 31-bit integer.
  4. Reduce. That integer modulo 10{{ digits() }}, left-padded with zeros.

In production the secret lives only on the server and the phone, is stored encrypted, and replay and lockout state is persisted per user rather than held in memory.
